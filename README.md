# Fagprojekt

Hybrid repository for embedded neural network experiments and offline signal analysis.

The codebase contains:

- C++/Arduino components for model inference/training pipelines.
- Core neural-network building blocks implemented in C++ (`Tensor`, layers, activations, losses, optimizer).
- Python scripts for data streaming, Fourier/signal analysis, and descriptive statistics.
- Generated analysis outputs in CSV/JSON/PNG format.

## Repository Layout

- `Fagprojekt.ino`: Arduino sketch entry point.
- `Tensor.*`: 2D tensor/matrix container and operations.
- `NNLayer.*`, `DenseLayer.*`: dense layer implementations.
- `Activations.*`, `Activationfunctions.*`: activation functions.
- `CategoricalCrossEntropyLoss.*`, `Activation_Softmax_CategoricalCrossEntropy.*`, `Loss.*`: loss functions and combined softmax+cross-entropy logic.
- `SGD.*`: stochastic gradient descent optimizer utilities.
- `Model.*`: model wrapper composed of layers/activation/loss.
- `tests/test.cpp`: Unity-based C++ test(s).
- `python_files/`: Python scripts for data ingestion, streaming, and analysis.
- `analysis_outputs/`: generated plots and summary statistics.
- `data/`: dataset/input files.

## Prerequisites

### C++ / Arduino

- Arduino IDE or PlatformIO (for `.ino` workflows).
- A board supported by your Arduino environment.
- Serial monitor support at `115200` baud (used by `Fagprojekt.ino`).

### Python

- Python `>=3.13`.
- Dependency manager compatible with `pyproject.toml` (for example `uv` or `pip`).

Dependencies declared in `pyproject.toml`:

- `numpy`
- `scipy`
- `matplotlib`
- `pyserial`


## Python Setup

Using `uv` (recommended when `uv.lock` is present):

```bash
uv sync
```

Alternative with `pip`:

```bash
python -m venv .venv
.venv\Scripts\activate
python -m pip install -U pip
python -m pip install numpy scipy matplotlib pyserial
```

## Running Python Scripts

Examples:

```bash
python python_files/data_analysis.py
python python_files/data_descriptive_stats.py
python python_files/fourierstreaming.py
```

If scripts expect local input files, ensure required files are available in `data/` or update script paths accordingly.

## Arduino Workflow

1. Open `Fagprojekt.ino` in Arduino IDE or your PlatformIO project.
2. Select board and serial port.
3. Build and upload.
4. Open serial monitor at `115200` baud.

The sketch is designed around frame-based serial input and can output predictions/probabilities in a comma-separated status format.

## Switching Between Classic And LOOCV Modes

Both `streaming.cpp` and `streaming_loocv.cpp` exist in the repository. They use C++ preprocessor guards to ensure only one implementation is compiled at a time:

- `streaming.cpp` is guarded with `#if !defined(STREAMING_USE_LOOCV)`
- `streaming_loocv.cpp` is guarded with `#if defined(STREAMING_USE_LOOCV)`

### Classic Mode (Default)

Compile normally without any special flags:

```bash
arduino-cli compile --fqbn arduino:mbed_nano:nano33ble .
```

Or in Arduino IDE: just build and upload as usual. This uses `streaming.cpp` and provides regular streaming/training flow.

### LOOCV Mode

Compile with the `-DSTREAMING_USE_LOOCV` flag:

```bash
arduino-cli compile --fqbn arduino:mbed_nano:nano33ble \
  --build-property compiler.cpp.extra_flags="-DSTREAMING_USE_LOOCV" .
```

This activates `streaming_loocv.cpp` for Leave-One-Out Cross-Validation testing. After upload, run:

```bash
python python_files/loocv_coordinator.py
```

### Helper Script

You can use `switch_mode.ps1` to view compile instructions:

```powershell
powershell -ExecutionPolicy Bypass -File .\switch_mode.ps1 -Mode status    # Show current setup
powershell -ExecutionPolicy Bypass -File .\switch_mode.ps1 -Mode classic   # Show classic build instructions
powershell -ExecutionPolicy Bypass -File .\switch_mode.ps1 -Mode loocv     # Show LOOCV build instructions
```

### CI/CD

The GitHub Actions workflow automatically builds both modes to catch regressions in either implementation.

## Testing

The repository includes Unity-style C++ tests in `tests/test.cpp`.

How you run tests depends on your toolchain:

- PlatformIO: run `pio test` if your test environment is configured.
- Arduino/Unity standalone: integrate the test file into your test runner setup.
